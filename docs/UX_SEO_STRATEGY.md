# UX_SEO_STRATEGY.md — UX, SEO/GEO, карточки, корзина, кросс-продажи и безопасность V2

## 1. Назначение документа

Документ описывает стратегию новой версии сайта магазина сантехники, которая создаётся параллельно старому сайту в папке `new-store-v2/`. Цель — сделать сайт максимально удобным и продающим за счёт сильного UX, технически полезных карточек, SEO/GEO-архитектуры, понятной корзины, кросс-продаж и базовой безопасности.

Старый сайт не меняется. Все решения ниже относятся только к V2.

## 2. UX-принципы V2

### 2.1. Главный принцип

Покупатель должен быстро понять:

- что это за товар;
- подходит ли он под его задачу;
- есть ли он в наличии;
- какие характеристики важны;
- какие документы доступны;
- что ещё нужно купить для монтажа;
- как быстро оформить заказ или запросить счёт.

### 2.2. Два типа покупателей

#### Профессионал / монтажник / закупщик

Ему важны:

- быстрый поиск по артикулу;
- фильтры по техническим параметрам;
- наличие и сроки;
- документы и сертификаты;
- возможность заказать много позиций;
- быстрый счёт;
- понятная спецификация корзины.

#### Частный покупатель

Ему важны:

- простое объяснение назначения;
- подсказки «подходит для»;
- готовые комплекты;
- консультация;
- доверие к бренду и магазину;
- отсутствие перегруза техническими деталями на первом экранее.

## 3. Архитектура главной страницы

Главная должна не просто показывать каталог, а вести к покупке.

Рекомендуемые блоки:

1. Первый экран:
   - короткое УТП;
   - поиск по каталогу и артикулу;
   - быстрые кнопки: «Подобрать товар», «Запросить счёт», «Каталог», «Консультация»;
   - гео/доставка: город, сроки, самовывоз/доставка.
2. Популярные задачи:
   - водоснабжение;
   - отопление;
   - насосы;
   - сантехника для ремонта;
   - фитинги и арматура;
   - комплектующие для монтажа.
3. Категории каталога.
4. Бренды: VALTEC, AQUARIO, ZOTA и другие.
5. Хиты/популярные товары.
6. Готовые комплекты.
7. Преимущества магазина:
   - техническая консультация;
   - документы;
   - подбор совместимых товаров;
   - работа с B2B;
   - доставка по городу/региону.
8. Полезные статьи и инструкции.
9. Контакты, адрес, карта, способы связи.

## 4. Каталог и категории

### 4.1. Навигация

Каталог должен быть доступен через:

- главное меню;
- поиск;
- блок задач;
- брендовые страницы;
- SEO-посадочные страницы;
- хлебные крошки.

### 4.2. Страница категории

Обязательные элементы:

- H1 с понятным названием;
- краткое описание категории;
- фильтры, релевантные категории;
- сортировка: популярные, цена, наличие, новинки;
- карточки товаров;
- блок популярных подкатегорий;
- блок брендов;
- SEO-текст ниже списка;
- FAQ по категории;
- внутренние ссылки на задачи, бренды, статьи.

### 4.3. Фильтры

Фильтры должны быть техническими, но не хаотичными.

Примеры:

- бренд;
- диаметр;
- тип резьбы;
- материал;
- рабочее давление;
- температура;
- мощность;
- производительность;
- напор;
- тип подключения;
- назначение;
- наличие;
- цена.

Правила:

- фильтры без товаров не должны перегружать интерфейс;
- выбранные фильтры должны быть видимы;
- должна быть кнопка сброса;
- SEO-индексация фильтров только для заранее выбранных полезных комбинаций;
- остальные фильтрованные URL — `noindex` или canonical на категорию.

## 5. Карточка товара

### 5.1. Первый экран карточки

На первом экране пользователь должен увидеть:

- название товара;
- бренд;
- артикул;
- главное фото;
- цену или способ запроса цены;
- наличие/статус поставки;
- ключевые характеристики;
- CTA: «В корзину», «Запросить счёт», «Получить консультацию»;
- доставку/самовывоз для выбранного города;
- рейтинг/отзывы, если они будут достоверными.

### 5.2. Галерея и фото

Целевой набор медиа:

1. Главное фото на белом/чистом фоне.
2. Фото под углом.
3. Фото крупного плана важных деталей.
4. Фото упаковки/маркировки.
5. Технический чертёж или размерная схема.
6. Схема подключения, если применимо.
7. Фото товара в монтаже, если доступно.

Требования:

- изображения оптимизированы;
- есть alt-текст;
- lazy loading для второстепенных изображений;
- без растянутых и битых фото;
- placeholder только временно и с отметкой в data-quality отчёте.

### 5.3. Описание товара

Структура описания:

- короткое назначение в 1–2 предложения;
- где применяется;
- ключевые преимущества;
- технические ограничения;
- что нужно проверить перед покупкой;
- чем отличается от аналогов;
- какие товары купить вместе.

Важно: описания должны помогать выбрать товар, а не быть пустым SEO-текстом.

### 5.4. Характеристики

Характеристики должны быть нормализованы:

- единые названия полей;
- единые единицы измерения;
- отдельные поля для важных фильтров;
- отсутствие дублей;
- сохранение оригинального значения поставщика при необходимости.

Примеры:

- бренд;
- серия;
- артикул;
- материал;
- диаметр;
- резьба;
- давление;
- температура;
- мощность;
- производительность;
- гарантия;
- страна производства;
- комплектность.

### 5.5. Документы

Карточка должна поддерживать:

- паспорт изделия;
- инструкцию;
- сертификат;
- декларацию;
- монтажную схему;
- гарантийные условия.

Если документа нет, это должно попадать в отчёт качества данных.

### 5.6. Блоки доверия

- официальный бренд/поставщик, если подтверждено;
- гарантия;
- сертификаты;
- консультация специалиста;
- реальные условия доставки;
- контакты магазина;
- безопасная обработка заявки.

## 6. Карточка товара в листинге

Карточка в каталоге должна показывать максимум полезного без перегруза:

- фото;
- название;
- бренд;
- артикул;
- 3–5 ключевых характеристик;
- цена/статус цены;
- наличие;
- кнопка «В корзину»;
- кнопка «Быстрый запрос»;
- значок документов/сертификата;
- подсказка «подходит для» при наличии.

Для технических категорий важно, чтобы артикул был виден сразу.

## 7. Поиск

Поиск должен поддерживать:

- артикулы;
- названия;
- бренды;
- категории;
- синонимы;
- опечатки;
- транслитерацию;
- популярные запросы;
- нулевые результаты с предложением альтернатив.

Страница нулевого результата не должна быть тупиком. Нужно показать:

- похожие категории;
- форму «помогите найти»;
- телефон/мессенджер;
- популярные товары;
- рекомендации по изменению запроса.

## 8. Корзина и оформление заказа

### 8.1. Цель корзины

Корзина должна позволять быстро отправить заявку или запросить счёт. Для сантехнического магазина это часто важнее классической online-оплаты, потому что заказ может требовать уточнения наличия, доставки, совместимости и скидок.

### 8.2. Функции корзины

- изменение количества;
- удаление товара;
- сохранение корзины;
- отправка корзины менеджеру;
- запрос счёта для юрлица;
- комментарий к заказу;
- выбор города;
- выбор доставки/самовывоза;
- подсказки по недостающим товарам;
- отображение сопутствующих товаров;
- печать/экспорт спецификации в будущем.

### 8.3. Минимум полей

Для быстрого запроса:

- имя;
- телефон;
- город;
- комментарий опционально.

Для B2B:

- организация;
- ИНН опционально;
- email;
- телефон;
- комментарий;
- файл/спецификация в будущем.

### 8.4. UX-правила

- оформление без регистрации;
- ошибки показываются рядом с полем;
- телефон валидируется;
- заявка подтверждается понятным сообщением;
- пользователь видит, что будет дальше: «менеджер уточнит наличие и срок»;
- корзина не должна теряться при обновлении страницы.

## 9. Кросс-продажи и рекомендации

### 9.1. Типы рекомендаций

1. Совместимые товары.
2. Нужны для монтажа.
3. Часто покупают вместе.
4. Расходники.
5. Аналоги.
6. Товары лучше по характеристикам.
7. Комплекты под задачу.

### 9.2. Rule-based старт

На первом этапе рекомендации задаются правилами:

- категория → сопутствующие категории;
- бренд/серия → совместимые товары;
- диаметр/резьба → совместимые фитинги;
- насос → автоматика, фильтры, обратный клапан, комплект подключения;
- отопительный котёл/оборудование → группа безопасности, расширительный бак, насос, арматура;
- смеситель/санфаянс → гибкая подводка, сифон, крепёж, герметик.

### 9.3. Где показывать рекомендации

- карточка товара;
- корзина;
- страница категории;
- страница задачи;
- после добавления товара в корзину;
- в заявке для менеджера как подсказка.

### 9.4. Метрики кросс-продаж

- CTR блока рекомендаций;
- добавления сопутствующих товаров;
- среднее количество позиций в корзине;
- средний чек;
- отказы после показа рекомендаций;
- ручные исправления менеджеров.

## 10. SEO-архитектура

### 10.1. URL-структура

Рекомендуемая структура:

- `/catalog/` — каталог;
- `/catalog/{category}/` — категория;
- `/catalog/{category}/{subcategory}/` — подкатегория;
- `/product/{slug}/` — товар;
- `/brands/{brand}/` — бренд;
- `/brands/{brand}/{category}/` — бренд + категория;
- `/solutions/{task}/` — страница задачи;
- `/geo/{city}/` или отдельная согласованная городская структура;
- `/articles/{slug}/` — статьи и инструкции.

Важно: итоговый вариант GEO-URL должен быть утверждён до генерации страниц.

### 10.2. Metadata

Для каждой страницы должны быть:

- уникальный title;
- description;
- H1;
- canonical;
- Open Graph;
- хлебные крошки;
- корректный robots meta.

Шаблоны не должны создавать одинаковые заголовки для тысяч страниц.

### 10.3. Schema.org

Нужные типы разметки:

- `Organization`;
- `LocalBusiness`;
- `Product`;
- `Offer`;
- `BreadcrumbList`;
- `FAQPage` для страниц с FAQ;
- `Article` для инструкций.

Для товара важно указывать:

- название;
- бренд;
- артикул/SKU;
- фото;
- описание;
- offer/price/availability, если данные достоверны;
- URL товара.

### 10.4. Sitemap и robots

Sitemap должен включать только полезные индексируемые страницы:

- категории;
- товары с достаточным качеством данных;
- бренды;
- важные GEO-страницы;
- статьи;
- страницы задач.

Не включать:

- пустые фильтры;
- технические страницы;
- корзину;
- результаты поиска;
- черновики;
- страницы с низким качеством данных.

## 11. GEO-стратегия

### 11.1. Цель GEO

Получать локальный трафик по запросам вида:

- купить сантехнику в городе;
- купить VALTEC в городе;
- насосы AQUARIO в городе;
- отопительное оборудование ZOTA в городе;
- доставка сантехники в городе.

### 11.2. Правила GEO

- использовать whitelist городов;
- не генерировать тысячи пустых страниц;
- каждая городская страница должна иметь реальную пользу: доставка, сроки, контакты, условия, популярные категории;
- избегать одинаковых текстов;
- использовать canonical/noindex там, где нет уникальной ценности;
- не обещать наличие или доставку, если это не подтверждено.

### 11.3. GEO-блоки

На городских страницах:

- H1 с городом;
- условия доставки;
- популярные категории;
- бренды;
- способы связи;
- FAQ;
- карта/адрес, если релевантно;
- ссылки на категории и задачи.

## 12. Контент-стратегия

### 12.1. Типы контента

- описания категорий;
- инструкции по выбору;
- статьи по монтажу;
- сравнения товаров;
- FAQ;
- страницы брендов;
- страницы задач;
- документы товаров.

### 12.2. Примеры статей

- Как выбрать шаровой кран VALTEC.
- Как подобрать насос AQUARIO для дома.
- Что нужно для монтажа радиатора.
- Какие фитинги нужны для полипропиленовых труб.
- Как читать характеристики насоса.
- Что купить вместе с водонагревателем.

### 12.3. Требования к текстам

- практическая польза;
- точность терминов;
- отсутствие переспама;
- ссылки на товары и категории;
- ответы на реальные вопросы клиентов;
- проверка технических утверждений.

## 13. Безопасность

### 13.1. Базовые требования

- не хранить секреты в репозитории;
- не выводить секреты в логи;
- серверная валидация форм;
- защита от спама;
- rate limit на формы и API;
- HTTPS на продакшне;
- secure/correct headers;
- ограничение CORS;
- регулярная проверка зависимостей;
- безопасная обработка пользовательского ввода;
- логирование ошибок без персональных данных сверх необходимости.

### 13.2. Формы

Для форм заявки:

- honeypot или captcha при подозрительной активности;
- ограничение частоты отправки;
- валидация телефона/email;
- защита от XSS в комментариях;
- понятная политика обработки персональных данных;
- запись согласия, если требуется.

### 13.3. Админка и доступы

Если в V2 появится админка:

- отдельные роли;
- MFA желательно;
- audit log;
- запрет публичного доступа к служебным эндпоинтам;
- защита upload-файлов;
- минимальные права.

## 14. Производительность

### 14.1. Цели

- быстрый первый экран;
- оптимизированные изображения;
- минимальный JS;
- lazy loading;
- кеширование;
- стабильная мобильная версия;
- отсутствие layout shift.

### 14.2. Изображения

- использовать responsive sizes;
- WebP/AVIF при возможности;
- CDN или статический кеш в будущем;
- fallback для отсутствующих фото;
- отдельный отчёт по битым изображениям.

### 14.3. Core Web Vitals

Контролировать:

- LCP;
- CLS;
- INP;
- общий Lighthouse score;
- размер JS bundle;
- количество запросов на карточке и категории.

## 15. Аналитика

### 15.1. События

Нужно фиксировать:

- поиск;
- нулевой поиск;
- просмотр категории;
- применение фильтра;
- просмотр товара;
- клик по фото/документу;
- добавление в корзину;
- удаление из корзины;
- отправку заявки;
- клик по телефону/мессенджеру;
- клик по рекомендации;
- запрос консультации.

### 15.2. Отчёты

Регулярные отчёты:

- самые частые нулевые поиски;
- товары без фото;
- товары без характеристик;
- товары без документов;
- категории с высоким отказом;
- рекомендации с низким CTR;
- формы с ошибками;
- страницы с низкой скоростью.

## 16. Data quality score карточки

Для контроля качества каждой карточке можно присваивать score.

Пример критериев:

- есть главное фото: +20;
- есть 3+ фото: +10;
- есть технический чертёж: +15;
- заполнены ключевые характеристики: +20;
- есть описание назначения: +10;
- есть документы: +15;
- есть кросс-продажи: +10.

Карточки с низким score не должны попадать в приоритетные SEO-разделы без доработки.

## 17. Acceptance checklist

Перед soft launch проверить:

- legacy-файлы не изменены;
- V2 находится внутри `new-store-v2/`;
- главная страница ведёт к каталогу, задачам и заявке;
- поиск работает по артикулу;
- категории имеют релевантные фильтры;
- карточки имеют фото, характеристики и CTA;
- корзина работает без регистрации;
- форма заявки валидируется;
- кросс-продажи отображаются логично;
- schema.org валидна;
- sitemap не содержит мусорных URL;
- GEO-страницы ограничены whitelist;
- формы защищены от спама;
- изображения оптимизированы;
- мобильный UX проверен;
- аналитика фиксирует ключевые события.

## 18. Итоговая стратегия
